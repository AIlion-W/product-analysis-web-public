# 产品分析助手

一个简约的单页商品分析网站。运营可以先看市场格局，再拆解多个竞品，也可以直接进入详情页分析、内功问诊、买家秀专项分析或全链路分析。原有分析模块生成可编辑的「分析主表 + 执行方案表」；内功问诊生成六区证据看板，并从同一份报告导出 HTML 和 Excel。

## 获取自己的副本

在 GitHub 仓库页面点击「Use this template」，即可在自己的账号下创建一份完全独立的源码仓库；也可以直接 Fork 或 Clone。仓库不包含任何 API Key、历史上传资料或分析结果。

## 当前范围

- 已完成「市场分析、多竞品对比分析、详情页分析、内功问诊、买家秀专项分析、全链路分析」6 个入口。
- 市场分析输出「市场格局表 + 对标竞品筛选表」，不从资料中编造市场份额、销量或转化数据。
- 多竞品对比分析支持文件夹或 ZIP 上传后的竞品分组确认，并可选择营销文案、视觉表达和页面框架分析维度。
- 内功问诊在浏览器内解析标准 Excel，按产品分批分析，重算聚合并校验证据链后才显示正式报告。
- 原有模块结果支持原文编辑、复制、下载 Markdown 和导出 Excel。
- 内功问诊固定展示「数据完整性、评价类型、默认前 20 条六维覆盖、问大家主题分布／竞品对照、分析结论、落地清单」6 个分区。业务主视图使用中文名称，内部证据编号放在「查看审计证据」中按需展开。
- 提示词和产品知识留在服务器端；上传文件和分析状态不持久化。

## 内功问诊用户流程

1. 选择「内功问诊」，填写我方产品名称。
2. 为我方分别上传默认排序评价 Excel、时间排序评价 Excel、问大家 Excel 和评价页截图；可再添加最多 3 个竞品，并为每个竞品上传同样的数据包。
3. 进入完整性检查，核对实际文件、工作表名称、字段映射、有效行数、使用行数和排除行数。
4. 逐个勾选「我已确认产品归属、工作表名称与字段映射」，再开始分批分析。
5. 主分析最多同时执行 4 个批次；单次模型响应超过 120 秒会主动中止并显示 `MODEL_TIMEOUT`，随后按可重试错误自动重试 1 次，不再无限停留在「分析中」。出现多个失败项时可点「并行重试全部失败批次」，系统只重跑失败项并保留成功结果，也可继续单独重试某一批次。只有竞品失败批次可以选择排除该竞品后继续。综合报告遇到超时、429、5xx 或网络错误会自动重试 1 次；最终失败后可点「重试综合报告」，且不会重跑已成功的 Excel 主任务。
6. 报告通过 finding → evidence 校验后进入问诊看板，可「下载 HTML」或「导出 Excel」。

关闭／刷新后本次问诊状态丢失。页面会在已经解析资料或正在分析时提示离开风险，但不会保存本次数据。

### 标准产品数据包

我方与每个竞品分别准备一套，推荐目录如下：

```text
产品数据包/
├── 评价数据表格-默认排序.xlsx
├── 评价数据表格-时间排序.xlsx
├── 问大家.xlsx
└── 评价页截图.png
```

- 默认排序评价和时间排序评价是两个独立的 `.xlsx` 文件，分别上传到对应的文件框。
- 两个评价文件分别读取第一个工作表；数据角色由上传框决定，不依赖工作表名称。
- 两个评价文件必须能映射出排名、昵称、评价时间、评价类型、SKU、初评正文和追评正文 7 个字段。系统会先做 NFKC 与首尾空格规范化，并兼容常见别名：`序号`／`排名`，`旺旺号`／`用户昵称`／`买家昵称`／`昵称`，`初评时间`／`评价时间`／`评论时间`，`初评`／`初评内容`／`评价内容`／`评论内容`，以及 `追评`／`追评内容`／`追加评价`／`追加评论`。
- `晒图/视频`、`有用`、`追评时间`、`追评晒图/视频` 等额外的非分析列只记录警告，不阻断预检；缺少必需语义字段或同一字段出现两个候选列时仍会阻断，避免误映射。
- `问大家.xlsx` 读取第一个工作表，支持两种输入：A）精确四列 `昵称`、`时间`、`问题`、`问答`，系统按 Excel 行序补排名；B）旧版表头必须带 `序号` 或 `排名`，并包含 `问题`、`回答`、`提问时间`。
- 单个 XLSX 压缩文件最大 10MB；系统在解压前检查单 entry／总展开大小和压缩比，异常压缩包会在完整性检查中阻断。
- 评价 Excel 和问大家 Excel 仅支持 `.xlsx`。截图支持 PNG、JPEG、WebP，浏览器会压缩为 WebP；无法压缩到 560KB 以内时，截图分析降级为 unavailable。
- 默认排序评价 Excel 和时间排序评价 Excel 都是阻断必需项；缺少问大家或截图会警告并保留可执行的逐条分析，但相应结论会显示「数据不足」。
- 临时锁文件（文件名以 `.~` 或 `~$` 开头）会被忽略。

### 样本门槛与导出

- 每个产品的默认评价、时间评价、问大家各最多使用前 100 条有效数据，超出部分记录为 `excludedOverLimit`。
- 0 条为 missing；1–89 条为 insufficient；90–99 条为 provisional；100 条为 complete。
- 展示倾向正式诊断要求我方默认排序评价和时间排序评价各不少于 90 条。
- 默认前 20 六维明细在默认评价达到 20 条时保留；正式六维诊断要求默认评价不少于 90 条。
- 问大家正式诊断要求我方不少于 90 条；单个竞品不足 90 条时，只排除该竞品的正式问大家对照。
- F02 的六维覆盖率和 F03 的问题主题集中度是运营关注信号，不直接证明产品缺陷或信息缺口；正式建议只引导优化邀评问题、问答与详情页证据。
- HTML 是可离线打开的六区审计报告，生成时间按北京时间显示，并保留截图标签、错误、警告、排除行和可展开证据；Excel 固定包含「数据完整性、评价逐条标注、前 20 六维、问大家逐条标注、分析结论、落地清单」6 个工作表，其中分析结论用「是否触发关注线／规则代码」表达阈值信号。两种导出都来自当前已校验的同一份 `ReportData`，不会再次调用模型。

## 全链路分析资料结构

全链路分析仍使用原通用评价逻辑，不调用内功问诊的独立解析器、证据图和六区导出。它优先按以下目录名称识别资料：

```text
待分析资料/
├── 01_市场资料/
├── 02_竞品资料/
│   ├── 竞品A/
│   └── 竞品B/
├── 03_详情页/
├── 04_评价区/
└── 05_买家秀/
```

无法归类的文件会列入「待确认」，不会被擅自分配给某个专项模块。

## 原通用模块上传限制

- 当前 Sites 生产环境单次直传预算约为 850KB；普通文件、ZIP 和文件夹的总上传体积超过该预算时，需要拆分或压缩。
- 每组最多处理 80 个有效文件。
- 单个解压文件最大 15MB，每组解压后总体积最大 60MB。
- 不支持加密 ZIP、ZIP64 和嵌套压缩包。

内功问诊不走上述通用上传接口：Excel 在浏览器解析后按每批最多 50 行提交，独立接口单个请求正文上限为 900KB。

## 本地运行

```bash
npm install
npm run dev
```

本地开发时复制 `.env.example` 为 `.env`，只在本地安全配置或部署环境的密钥管理中填写模型服务凭据，不要把凭据或私有中转地址提交到仓库。

最低需要配置：

```dotenv
OPENAI_API_KEY=你的模型服务密钥
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-5.6
ANALYSIS_MODEL_TIMEOUT_MS=120000
NEIGONG_MODEL=
NEIGONG_VISION_MODEL=
NEIGONG_MODEL_TIMEOUT_MS=120000
PRODUCT_ANALYSIS_PROXY_TOKEN=仅供受信任服务端代理使用的随机强 Token
```

`NEIGONG_MODEL` 可单独指定内功问诊文字分析模型；留空时继承 `OPENAI_MODEL`。Claude 型号会自动改走 `/v1/chat/completions`，其他型号继续使用 `/v1/responses`。`NEIGONG_VISION_MODEL` 只控制截图识别；留空时继承 `OPENAI_MODEL`，不会继承 Claude 文字模型。模型结果仍会经过固定目录、原始行引用和严格 Schema 校验，中转站未严格执行 `json_schema` 时也不会直接采用未经校验的自由输出。

## 部署到 Cloudflare Workers

项目使用 vinext，原生部署目标是 Cloudflare Workers。

1. 安装依赖并登录 Cloudflare：

```bash
npm install
npx wrangler login
```

2. 在 Cloudflare Dashboard 的 Worker「Settings → Variables and Secrets」中配置 `OPENAI_API_KEY`，并按需配置 `OPENAI_BASE_URL`、`OPENAI_MODEL`、`ANALYSIS_MODEL_TIMEOUT_MS`、`NEIGONG_MODEL`、`NEIGONG_VISION_MODEL`、`NEIGONG_MODEL_TIMEOUT_MS`。接入 Nuwa 时还必须把 `PRODUCT_ANALYSIS_PROXY_TOKEN` 配置为 Secret，并在 Nuwa 服务端配置相同 Token。密钥必须使用 Secret 类型。

Nuwa 仅调用强制 Token 鉴权的 `/api/nuwa/analyze` 与 `/api/nuwa/neigong/analyze`。原公开页面继续使用原有接口和原有分析路径；动态知识只允许进入通用分析，内功问诊仍执行固定目录、严格 Schema 与证据链，不注入动态知识。

Nuwa 专用路由的模型配置由 Nuwa 服务端在代理请求中读取网站「模型管理」里的默认对话模型和默认视觉模型，并在代理 Token 校验通过后使用；因此接入 Nuwa 时无需在 Worker 中重复配置 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`、`NEIGONG_MODEL` 或 `NEIGONG_VISION_MODEL`。这些环境变量继续仅供本仓库原公开页面和独立部署使用。模型凭据不会进入浏览器、分析请求正文或接口响应。

3. 部署：

```bash
npm run deploy -- --name product-analysis-web
```

首次部署时也可以通过环境变量提供 `CLOUDFLARE_ACCOUNT_ID`。部署完成后，Wrangler 会返回可访问的 `workers.dev` 地址。
